## 2. 两套签名算法必须分开实现（最容易写错的地方）

| | 入站/出站（gqxq -> public-utility） | 回传（public-utility -> gqxq） |
| --- | --- | --- |
| canonical | `v1` + LF + METHOD(大写) + LF + path + LF + timestamp + LF + nonce + LF + sha256(原始 body) | `epochSeconds` + LF + sha256(原始 body) |
| 参与段 | 6 段 | **2 段**（没有 v1、没有 method/path/nonce） |
| 请求头 | X-PU-Key-Id / -Timestamp / -Nonce / -Signature | X-Public-Utility-Key-Id / -Key-Version / -Timestamp / -Event-Id / -Signature |

**两者都必须对原始 body 字节求摘要**。出站侧把这一点做成了类型约束而不只是注释：

```text
serializeOnce(payload)   -> SerializedBody{ bodyText, bodyBytes, bodySha256 }   // 唯一一份字节
buildAttempt(serialized) -> SignedAttempt{ signature, bodyBytes }              // 同一 Buffer 引用
fetch(url, { body: attempt.bodyBytes })                                        // 绝不再 stringify
```

重试循环只换 nonce 与时间戳。库级证据（`dispatch_request_log`）：同 requestId 的两次尝试 body_sha256 逐字相同、nonce 不同：

| request_id | attempt / result | nonce | body_sha256 |
| --- | --- | --- | --- |
| AREQ…0009 | replay → success | d47602a7… / ec5817e6… | 均为 497c6c58…814d |
| AREQ…0015 | timeout → success | ccb1ca17… / 1c1045ee… | 均为 fa7443f6…bbd5 |

## 5. 实现取舍与已知缺口

| 项 | 说明 |
| --- | --- |
| **契约缺口：无法表达企业签收** | 事件枚举只有 4 种，所以 status=accepted 不经回调到达。已如实注释，**未自造事件类型**。G3 启动前需与对方书面确认（独立订阅 or 任务创建响应回执） |
| 时钟偏差超限返回 503 而非 401 | 对方把 5xx 视为可重试、401 视为永久不重试；返回 401 会让合法事件因时钟漂移被永久丢弃 |
| ackValue 超过 500 字节判为配置错误 | business_event.ack_body 是 varchar(500)，超长会截断导致重复投递的 ACK 与首次不一致 |
| 5xx 归到 network_error | 冻结的 PushResultKind 没有「服务端错误」档；5xx 与网络错误可重试性同类，httpStatus 已记入日志 |
| 撤销不回退 complaint.reporting_status | 对方确实已建任务，回退会让本地与实际不一致 |
| 被拒事件重复投递返回 400 而非 200 | 若返回 200，发送方会以为成功，而该报文永远不会被人工处理 |
| D4 未落地 | app=gqxq / 模板 GQXQ_SENSITIVE_DISPATCH v1 / 审批定义 GQXQ_SUPERVISION_APPROVAL v1 / 订阅 GQXQ_TASK_RESULT 需在对方登记；这是真实联调的前置 |
| 附件下载与存证 | D6，未做 |

## 6. 两条线各自修掉的脚手架缺陷（教训，值得记）

| 线 | 缺陷 | 后果 |
| --- | --- | --- |
| G3 | 桩把故障注入放在路径校验之前 | 就绪探针会提前吃掉一次性的 `--timeout-once`，超时分支**假失败** |
| G3 | 桩在 body 超限时 destroy 连接 | 客户端看到 ECONNRESET 而非 413，结论错误 |
| G4 | 脚本没从 .env 读 DB 口令，且把错误信息里的 1045 当成查询结果 | **断言拿到假数字** |
| G4 | 用 reportingStatus 而非契约的 reportingStatusCode | G4-① 误判 FAIL |

共性：这四条都会让验收得出**与事实相反**的结论，而不会报错。测试脚手架本身也需要被审视。
