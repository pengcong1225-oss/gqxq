## 2. 数据库约束是唯一交办的裁决者（G2 的地基）

MySQL 不支持部分唯一索引，因此用**生成列 + 唯一键**实现：

```sql
active_complaint_id = IF(status IN ('pending','pushed','accepted','processing','returned'), complaint_id, NULL) STORED
UNIQUE KEY uk_active_dispatch (active_complaint_id)
```

NULL 不参与唯一去重，所以终态交办不占名额。直接对库做的判定性测试：

| 测试 | 结果 |
| --- | --- |
| 同一诉求插第 2 条**进行中**交办 | 失败：Duplicate entry '...' for key 'dispatch_order.uk_active_dispatch' |
| 同一诉求插**终态**（archived）交办 | 成功 |
| 重复 request_id | 失败：uk_dispatch_request |

迁移还带**先验检查**：若既有数据已违反唯一性，迁移会列出冲突诉求并拒绝执行，而不是静默失败。

## 4. 幂等的实现方式（关键设计）

**没有用先查后插**：创建交办直接 INSERT，唯一性交给 `uk_active_dispatch` 裁决；
撞键 → 事务回滚 → 按 complaint_id 回读进行中交办 → 返回 `created=false` + 既有记录（HTTP 200，不报错）。
若撞的不是有效交办键而是 request_id，回读会落空，此时按 409 冲突处理（不静默）。

撤销则先 `select ... for update` 锁行再判状态——否则两个并发撤销会同时通过状态检查。
