## 3. 前端四页的完整链路端到端实测

入站建诉求 → 建交办 → 推送(桩 taskId=9001) → `TASK_SUBMITTED` → 交办 processing → `TASK_APPROVED(AGREED)` → 交办 completed
→ **自动生成 8 项纠偏** → 逐项确认 → 分析库 total=1 且命中该诉求 → 报告待办 total=1 → 归档 200。

两个顺带被证实的后端行为：跳过 `TASK_SUBMITTED` 直接发 `TASK_APPROVED` 会被**正确拒绝推进**（`processed_result=ignored`，事件不丢）；纠偏未确认时归档返回 409 并写明「仍有 8 项待纠偏」。

## 4. 本轮修掉的两个缺陷

### 4.1 坐标写回非数值返回 500（应为 400）

前端线实测发现：对 `location_lng/location_lat` 的 confirm 传非数值会返回 **HTTP 500**。根因是把请求里的字符串直接绑进 DECIMAL 列的 SQL，MySQL 直接报错。

已修：写回前按列做类型校验（数值列必须可解析为有限数值，且经度 -180..180、纬度 -90..90），不合法抛 400 VALIDATION_FAILED。实测：

| 用例 | 修复前 | 修复后 |
| --- | --- | --- |
| 中文值 | 500 内部错误 | **400** + `fieldErrors[「经度 只能填数值，收到的是「中文地址」」]` |
| 超范围 999 | —— | **400** + 说明有效范围 |
| 合法 111.3000 | —— | **200** 且写回成功 |

### 4.2 字段版本里的旧值是写死的 null

同一次排查中发现 `writeBackToComplaint` 写 `complaint_field_version` 时 `oldValue` 恒为 `null` —— 等于审计里丢掉了「改之前是什么」，违反计划要求的「保存旧值/新值」。已改为从当前行取真实旧值。实测：`old_value = 111.28600000`、`new_value = 111.3000`。

> 验证过程中我踩了一次假阴性：第一次测试仍返回 500，原因是**服务跑的是修改前的 dist**（改了 src 没重新构建）。重建后才复现出正确结果。

## 5. 前端实测发现、由我补进契约的三处形状

这三条**只做静态类型检查一个都发现不了**，是前端线真跑接口才撞出来的：

| 接口 | 实际形状 | 处置 |
| --- | --- | --- |
| `GET /complaints/:idOrNo/corrections` | **裸数组** `CorrectionItem[]`（只有 `/corrections/pending` 是分页封套） | |
| `GET /analysis/records/:analysisId` | **嵌套** `{ record, complaint, dispatch, approvalTraces, corrections, reportTodo }`，字段名是 `approvalTraces` 复数 | 已提升为对外契约 `AnalysisDrilldown` |
| `POST /corrections/:id/confirm` 与 `/reject` | `{ item, analysisEntered, analysisId, analysisReason, writtenBack }` | 已提升为对外契约 `CorrectionDecisionResult`；并明确「是否入库由后端判定，前端不得靠数 pending 项推断」 |

起因是我钉契约时只钉了请求/响应，**没有为下钻与决策响应定义 DTO**，于是它们成了运行时才发现的事实。现已补进两侧 types/api.ts。

## 6. 实现取舍与已知缺口

| 项 | 说明 |
| --- | --- |
| 「未纠偏不得入分析库」**不是数据库 CHECK** | MySQL 无跨表 CHECK。实际是「锁 complaint 行 + 事务内 count(pending)」串行化 + `uk_ar_complaint` 唯一键兜底。这是能达到的最强形式，代码注释已写明，避免后人误以为有约束保护 |
| 回调里的纠偏生成与「审批通过」同事务 | 放事务外会留下「已批准却永远没有纠偏待办」的中间态——看起来链路走完了，实际分析库永远不会入库 |
| 加锁顺序固定 complaint → correction | 避免与其它路径交叉加锁造成死锁 |
| 坐标拆成两项 | `location_lng` / `location_lat` 各一项，写回无歧义 |
| `disposal_result` 无对应列 | 确认值只用于生成分析记录，不写 complaint |
| 报告正文/审批/发布 | 后置，本批次只做待办入口 |
| 附件下载与存证 | D6，未做 |
| 未做浏览器级渲染验收 | 前端证据止于类型检查 + 构建 + 真实接口契约断言；建议人工在四个页面各看一眼空态与「—」 |
