# 登录与操作日志使用说明（A6）

审计查询需要角色的 `system.audit.read` 权限。管理员在“角色权限”中配置后，重新获取当前身份即可出现“登录与操作日志”菜单；管理员角色名本身不能绕过被收回的权限。没有该权限时手输页面地址或直接请求 API 都拒绝。

1. 打开“登录与操作日志”（`/system/audit-logs`）。列表按时间、同刻写入序号倒序排列，分页可选每页条数，空结果如实显示。
2. 按日志类别选“登录日志”或“操作日志”；时间区间按浏览器当地时间输入。填写“操作人”的用户 ID 或用户名，点击“查询”。失败登录可按当时输入的用户名定位，即使该用户不存在。
3. 对建号、授权或停用，在“动作”输入 `USER_CREATE`、`USER_UPDATE`、`USER_SCOPE_UPDATE`、`ROLE_CREATE` 或 `ROLE_UPDATE`。角色前后值、账号状态及必要授权字段在详情中查看。口令设置仅有事实标志，不显示口令或哈希。
4. 对诉求处理，输入诉求编号（例如隔离测试的 `NO-C1`）或稳定业务键，选择“纠偏”/“交办”等模块。纠偏动作有 `CORRECTION_CONFIRM` / `CORRECTION_REJECT`，交办有 `DISPATCH_CREATE` / `DISPATCH_PUSH`，原件访问为 `SOURCE_DOCUMENT_READ`。关联业务日志以当前诉求范围为准；授权收回、对象移出范围或软删除后，列表计数和直查详情同时不可见。
5. 点击“查看详情”。“安全详情”展示审计 ID、时间、操作人、动作、结果、客户端 IP 和允许字段及前后值。结果为统一的成功/失败/拒绝/重复/未知，并保留历史原始结果；详情没有允许字段时显示对应空态。
6. 修改筛选条件后点“查询”会回到第一页；“重置”清除所有条件。查询或详情失败显示错误，刷新核对授权或请求条件后重试。

具备审计权限但无业务范围的账号可查看账号、登录、角色和明确的系统维护/安全拒绝事件；不能据此查看业务日志。权限拒绝事件隐藏原 URL、对象编号与自由文本，历史敏感词重扫隐藏全域统计。未知或无法解析归属的业务事件不公开，报告事件当前尚无 D3 稳定归属映射，默认不显示。

安全详情使用服务端动作白名单；不输出整份历史 detail、诉求正文、签名、令牌、原始来源/回调报文或任意嵌套对象。处置 JSON 的旧值和新值仍按 A2 已批准的六个标量字段投影。原始日志证据保持不变。页面没有导出、修改或删除日志功能。

开发验收仅在 `gqxq_a6_contract_test` 使用虚构账号与诉求。组件回归真实执行了失败登录、建号、角色改变、纠偏确认与审计检索；前端回归通过 Axios 假适配器验证菜单/页面权限、按操作人和业务号筛选、第二页和详情。未在业务库写入演示数据，也未宣称完整历史 schema、部署重启或生产验收通过。
