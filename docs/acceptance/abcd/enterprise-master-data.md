# 企业档案与服务户数维护

企业维护需要 `enterprise.manage`，企业查询需要 `enterprise.read`，服务端还会核验实际企业范围。企业管理能力不授予诉求原件权限。

登记编码是稳定主体键，新增后不能修改。编辑先读取当前档案版本，版本冲突时保留表单，刷新核对后再提交。联系人、联系方式、信用代码、注册地址与服务范围说明均来自实际登记，缺失信息显示为空或未知。

“档案管理归属区县”是人工明确登记的企业档案管理归属，须选择真实区划码。系统不会从地址或服务范围文字推断区县。该字段不表示服务覆盖范围，也不代表服务户数的区县分配。旧企业未登记该字段时，区县限定规则不能访问；明确的企业编码限定规则仍按授权规则生效。跨出当前授权范围的修改会回滚。

服务户数区间采用 `[生效日, 截止日)`，开始日包含、截止日不包含。截止日为空表示持续有效。新增较晚版本会结束上一开放区间；其他交叠会拒绝，历史值不能覆盖。例如 2026-01-01 起 20000 户、2026-07-01 起 30000 户，2026-06-30 仍取 20000 户。留空表示未知，0 表示核实为零，这两种分母均不能计算每万户诉求率。全企业户数不能直接与区县局部诉求分子搭配；期末或期均口径由统计规则显式选择。

来源部门映射使用“来源系统 + 来源部门码”，名称与别名只供展示和人工核验。未核验映射不参与自动关联，别名不会自动归并企业。政府机构不能登记为企业主体，已登记映射不能直接跨企业改绑。

停用须填写依据，已有企业、交办、网格或统计引用均保留。历史交办名称和报告快照不随改名重写。停用企业不再出现在新交办目标选单中。目标选单只展示登记编码、名称、业务类型和启用状态；看到目标选项不代表取得企业经营资料或该企业诉求的读取权限。
