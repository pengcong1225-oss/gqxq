# gqxq 实施决策与业务影响

这些决策用于完成已授权的 A—D 开发。候选统计口径、历史数据缺失处理和外部系统契约分别标明，便于实施和验收人员判断后续工作；它们不构成业务部门对正式指标或外部接口的确认。

## 身份与访问范围

| 决策 | 系统行为 | 业务影响或调整成本 |
|---|---|---|
| 平台用户主键保持稳定 | 既有业务引用继续使用本地用户；未来钉钉身份映射到该用户 | 钉钉适配须处理唯一匹配、冲突与撤销，不能直接换掉业务主键 |
| 角色功能与数据范围分别授权 | 管理员角色不自动等于全域数据范围；空范围拒绝访问 | 初始化及培训要同时配置功能和范围 |
| 单条范围规则内部取交集，多条规则取并集 | 企业与辖区条件必须按完整规则匹配 | 授权人员需按实际职责配置，不能把所有企业、辖区分别拼成更大范围 |
| 每次业务请求执行当前授权 | 停用、角色调整、范围调整和会话版本变化影响后续访问 | 界面缓存不能充当权限依据；管理员修改后可能使已有页面操作被拒绝 |
| 内部身份独立于角色 | 账号类型为内部、企业或未确认；历史账号默认未确认 | 主管回访结论需先维护内部类型，再授予结论权限 |
| 新钉钉基础身份待授权 | 新身份默认未确认，零业务角色、零数据范围；旧账号保持已维护类型 | 首次登录可能进入待分配页面；不能按钉钉部门或管理员标识自动提权 |
| 原始资料与日常业务投影分开 | 普通详情仅返回安全字段；原始来源资料需要独立能力、当前范围和审计 | 部分提供方自定义字段在正式映射前不会出现在普通结果中 |
| 日志按实际对象关联 | 已知动作使用真实主键与当前范围；未知或无法定位的对象日志默认不显示 | 新模块必须补日志对象映射；部分历史日志需补明确定义后才能查询 |

## 纠偏与主数据

| 决策 | 系统行为 | 业务影响或调整成本 |
|---|---|---|
| 人工有效值由统一版本保护 | 有效值变化递增诉求编辑版本，保存当刻新旧值和保护证据 | 旧窗口保存会收到冲突，操作人员需刷新后核对 |
| 来源接收时间不代表来源业务顺序 | 保留来源快照与差异，不把后到报文直接解释为更新的业务事实 | 真实来源顺序契约未就绪时，部分冲突需要人工核验 |
| 不重开历史纠偏和分析流程 | 字段保护不自动撤销分析入库，也不批量创建新的待纠偏项 | 历史重算或流程调整属于另外的明确工作 |
| 跨范围有效值修改必须有授权 | 将诉求改到操作者无权访问的企业或辖区时回滚 | 跨界纠偏需由具有相应范围的人员完成；合法的独立交办目标仍按交办规则处理 |
| 固定协议编码与可维护字典区分 | 既有协议编码只能治理标签、顺序、启停；流程状态只读；正式分类独立维护 | 扩展协议编码须同步调整集成契约，不能仅新增一条字典记录 |
| 企业行政归属与服务人口分开 | 企业辖区用于主数据权限，不充当服务覆盖或户数分布依据 | 区域投诉数不能自动除以企业全部户数作为区域发生率 |
| 户数保留生效期与版本 | 缺失、未知和零户数分别表达；不以当前值补造历史值 | 历史指标可能暂不可计算，需要补充有依据的历史主数据 |
| 全网格信息需要覆盖全对象的范围 | 多辖区、多企业网格的整体边界与成员必须全部可见 | 只拥有部分辖区权限的人员可能无法查看整体网格 |
| 服务网格登记与发布覆盖分开 | 草稿可先登记身份，提供真实有效日期和覆盖后发布 | 导入草稿不能自动产生空间统计依据 |
| 基础数据导入采用整批校验和事务 | 预览不写主数据，确认时复核版本和权限；失败不保留部分成功写入 | 遇冲突需重新预览；模板缺行不等于删除，人员和诉求不在本次导入范围 |
| 位置作为一组保存 | 地址、区划、坐标、网格关系原子校验；审计保存数据库实际精度值 | 缺边界或坐标系依据时提示无法判断，不假定选点就是可验证坐标 |
| 回访事实与办理状态独立 | 回访保留版本和更正理由，不直接改变来源、交办或办结状态 | 结论权限单独授予；正式满意度仍待业务口径确认 |

## 交办发送与恢复

| 决策 | 系统行为 | 业务影响或调整成本 |
|---|---|---|
| 用户明确推送后持久排队 | 交办创建本身不外发；最终入队时重新核验当前授权和数据 | “已排队”表示平台接收发送意图，不能解释为对方已建任务 |
| 已提交发送意图由服务执行 | 之后撤销用户权限不会删除已经合法提交的任务；新重试和查询仍需当前授权 | 撤权不是撤回已提交业务的方式；业务撤销仍按交办规则处理 |
| 原始请求字节不可变 | 重试引用同一快照；不换请求号、不按当前诉求重新生成旧请求 | 旧记录无原始证据时不能进入新恢复任务；保留已有任务关系并提示核查 |
| 未知结果默认人工核查 | 超时、发送中租约过期或缺有效任务编号时保留未知，不当作从未发送 | 部分实际未发送的旧记录也会等待核验，以避免重复创建对方任务 |
| 自动重复发送需明确提供方契约 | 只在配置明确且目标身份与合同版本匹配时，按原字节恢复 | 参考源码和虚构提供方测试不能证明线上部署保证；真实联调后才能配置 |
| 任务完成需持有有效租约 | 日志、业务关联、任务结果和审计在同一事务提交 | 失去租约的执行器不能覆盖较新的结果；历史交办结果不推进当前轮次 |

## 统计与报告的实施口径

以下 D 项已实现并通过任务级复核；全分支结论与验收边界以交付进度表为准。

| 决策 | 实际行为 | 业务影响或调整成本 |
|---|---|---|
| 总账与分析库显式区分 | 分析库同时明确当前值或入库快照视图，查询不能隐式混用 | 使用者要先选择正确数据集和视图 |
| 旧入库记录不补造业务日期 | 有日期的快照统计排除缺日期记录并说明数量；旧无日期记录浏览继续保留 | 历史比较可能显示不完整或不可计算，不能当作零 |
| 候选比较规则单独命名 | 月、季、年、自定义及部分期间规则可复算，始终标注待业务确认 | 业务采用其他口径时需要新增政策版本，不能回写旧报告解释 |
| 历史空间关系使用对应业务日 | 坐标及坐标系有依据，覆盖版本在当日有效，才建立网格归属 | 今天的位置核验不能证明历史归属；多网格桶不可简单相加 |
| 重叠历史覆盖先选最高有效版本 | 获选版本不适用或无权访问时不退回旧版本；冻结实际适用的业务日 | 热力和报告须复用确定的日期与网格结果，不能只看旧版本开放的生效期间 |
| 每万户指标要求人口范围匹配 | 只有能证明完整企业人口范围时才使用期末历史户数；局部范围返回原因 | 不能用全企业户数为无依据的局部指标兜底；期末规则仍是候选政策 |
| 户数主数据另存原范围依据 | 在同一读快照中保存真实授权企业的原行政归属，与诉求归属分别核验 | 企业后续改辖区不能改变旧报告的原范围证明；无权资料不会补入快照 |
| 统计工作量有显式上限 | 覆盖按版本区间批读，趋势单遍汇总；诉求量、覆盖版本、几何及计算工作超限则拒绝整次查询 | 大范围使用需缩小筛选或规划容量，不能返回被截断的总数与证据；详细限额见统计契约 |
| 热力正式发布需确认依据 | 开发支持规则草稿、计算和版本；正式发布校验对应版本的确认事实 | 虚构真值表只验证计算机制，不能自动产生正式颜色政策 |
| 热力候选政策必须自洽 | 上界锚点的首界以下固定为绿档，下界锚点的最高档固定为红档；矛盾组合不可发布并给出原因 | 不默默忽略政策字段；此约束只保证规则可计算，不能替代 Q7 业务确认 |
| 热力着色需要明确分类 | 未选具体正式分类时显示网格数量和选择提示；不挑混合分类中的主导颜色 | 全分类概览暂不提供一个混合颜色；逐诉求点位还需明细权限 |
| 报告冻结数据与版本 | 重试使用已冻结统计事实、模板版本和范围；下载再查当前完整授权 | 失去覆盖整份报告的权限后无法继续下载；不能按现值静默重算旧报告 |
| 报告保存原查询域 | 查询、比较区间和当时实际使用的授权规则一起冻结，空结果也核验范围 | 只有当前有权覆盖整份原查询域及原始、当前贡献对象的人员可访问，不能仅凭创建者身份放行 |
| 报告与旧办理入口并发时明确提示忙 | 报告按父对象顺序锁定，最后取得诉求锁时遇忙立即回滚；生成忙态不产生成功文件或完成待办 | 短时间内可能需要刷新或由有重试权限的人员重试原快照，避免与旧先锁诉求的分配入口互相等待 |
| 报告组件验收与整体部署验收分开 | 实际输出检查、独立进程恢复只证明相应组件 | 正式历史库迁移和 F 整体恢复仍需要单独执行 |

## 验证和交付限制

已授权的开发使用隔离工作区、虚构样本、本地独立 MySQL 库和假传输。完整基线缺失时采用明确声明的组件结构并调用实际迁移，不宣称它等于正式历史库。实现与独立复核均按用户要求使用 GPT-6.1 Sol High；工作保留在本地分支，尚未推送或部署。

实际运行日志、任务报告和审查报告保存在实施工作区的 `.superpowers/sdd/2026-10-09-abcd-delivery-plan`。这些原始证据应与成果一起保留，不能仅因代码已提交就删除。个别未阻断任务的界面提示、代码可读性和交办 nonce 日志问题仍进入最后的全分支审查。
