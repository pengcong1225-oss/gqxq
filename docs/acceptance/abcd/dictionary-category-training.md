# 通用字典与正式大小类操作说明（B1）

编制日期：2026-10-09。此说明对应开发功能；生产迁移、真实分类批量映射和完整交付验收另行安排。

## 管理权限与使用范围

“字典管理”使用当前服务端授权的 `system.dict.manage`，角色名称本身不授予权限。正式分类可选项需要 `dict.read`；分类纠偏需要 `complaint.correct`，还必须能访问该诉求当前所属企业/区划范围；分类历史使用 `complaint.read` 和同一当前对象范围。引用列表只列出当前范围内最多100条诉求，范围外及历史引用仍可能阻止删除。

`business_type`、`complaint_type`、`urgency_level` 是固定协议编码：只维护合法编码的标签、排序和启停，不新增未知协议码。状态轴及交办/触发/接收结果协议枚举只读，状态流转继续由业务流程控制。敏感词仍使用专用页签和原有最后启用词保护，不通过通用字典接口维护。

停用限制新的人工选择和改选。已经保存的历史取值继续可读；来源系统投递的已知协议码仍作为来源事实如实保存，不因管理员停用而丢弃或改成其他编码。字典全部停用时可选项为空，不会回退静态枚举重新出现。

## 通用字典操作

新增类型和条目默认草稿；发布后不能物理删除，只能停用保留历史。编码不可修改、不可重复，草稿删除后编码也永久保留，不能复用。条目支持两级：根项/大类和子项/小类。不能选择不存在的父项、形成循环、创建第三层，启用子项不能挂到停用父项，发布子项前需发布父项。

停用父项时，必须勾选“明确确认：停用父项时同时停用所有小类”；停用类型需确认停用全部条目。重新启用父项不会自动启用子项，需要逐项核实。已发布或被引用的条目禁止物理删除。删除未发布、未引用草稿前会确认，服务端仍检查真实引用。

切换字典或当前身份/授权版本变化时，页面清除旧条目、引用和编辑器；旧请求的响应不会替换当前字典。新增类型保存后切换并读取新类型。维护请求携带编辑时所属字典及读取时的条目/类型版本。如果另一窗口已修改，服务端返回409，编辑内容保留；刷新核对后再提交，不要用重试绕过冲突。没有实际变化的提交不增加版本、不制造新的审计事件。

## 正式分类纠偏

正式大小类单独维护于 `complaint_category`，与原有“诉求性质”（投诉、咨询等）并存。切换大类会清除不兼容小类；大类必选，小类可不选。保存时带分类字典版本、诉求编辑版本和核对依据。

诉求详情显示当前正式分类、来源分类（如已明确保存）以及修订历史；纠偏表单的“正式大小类”使用同一服务端选项。旧诉求缺少正式分类时显示“未分类”，不自动把旧 complaint_type 转成大小类，也不因新增nullable列批量增加待纠偏或清退既有分析记录。

对已经进入分析库的诉求重分类，仍要求全部纠偏已处理且曾有交办。通过当前分类纠偏项确认时，仅把正在确认的这一项作为本次已处理项，其他待纠偏、空状态或未知历史状态仍阻止改类。分类修订、保护状态、共享编辑版本、字段历史和审计在同一事务中保存；来源重传不能覆盖人工正式分类，尝试覆盖会留拒绝证据。

## 版本、分析与日志

当前正式分类使用 `major_category_code/minor_category_code/category_dictionary_version`，分类修订保留旧、新编码及各自字典版本。字典版本快照保留当时的标签、父项和状态。因此停用或后续标签变化不删除过去的分类含义。

旧 analysis_record 的存储保持原值。D1 已提供候选分类统计，分析库可显式选择当前有效值或实际入库快照；“入库记录浏览”保留无日期旧记录、原入库字段、筛选和分页，不把缺失日期补进日期统计。D3 已冻结同一统计快照、分类字典版本、原范围事实和当前范围证明，生成工程草稿 DOCX/XLSX；后续分类变化不回写已成功的产物。候选政策、实际历史报告兼容性和生产验收仍需各自的业务/外部证据。

“登录与操作日志”的模块“通用字典与大小类”可查明确字典配置事件；分类修订动作 `CATEGORY_REVISE` 属于诉求日志，按当前对象范围过滤。日志明细只显示允许的分类/版本元数据，不公开任意原始JSON、核对依据或来源报文。
