# 责任单位（企业）主数据需求清单

- 日期：2026-09-18
- 提出者：诉求平台研发
- 收件方：业务方 / 宜接就办数据接口负责人
- 目的：G2「诉求 → 责任单位」匹配规则要用**权威主数据**做匹配基准，现库数据不可用。本文是可直接转发的需求说明。

---

## 1. 为什么现在就要（不是"做完功能再说"）

G2 的匹配规则是"按名称把来源的承办单位对应到平台的企业/机构档案"。当前 `enterprise` 表只有 4 条基线数据：

| enterprise_code | enterprise_name | business_type |
| --- | --- | --- |
| ENT-GAS-001 | 宜昌中燃城市燃气有限公司 | gas |
| ENT-LPG-001 | 宜昌蓝天气体有限公司 | lpg |
| ENT-WATER-001 | 宜昌市供水总公司 | water |
| ENT-WATER-002 | 点军区供水有限公司 | water |

而真实来源数据（宜接就办 2026-09-17 导出，464 条诉求）里出现的供水企业是 **浦华三峡水务**（正文中亦作"三峡浦华水务"）。**"宜昌市供水总公司"在本批数据中一次都没有出现**。

风险不在"匹配不上"，而在**匹配上但匹配错了**：如果拿一份过时/臆造的企业档案去跑匹配，系统会给出一个"看起来成功、实际是错"的责任单位，并据此生成交办单推到对方系统——这比匹配失败危险得多，也正是本平台"零 mock 兜底"纪律要防的情况。因此：**在拿到权威主数据之前，G2 匹配规则不做真实验收**。

---

## 2. 需要提供什么

### 2.1 企业主数据（必填，用于责任单位匹配）

| 字段 | 说明 | 是否必填 |
| --- | --- | --- |
| 企业全称 | 工商登记全称 | 必填 |
| 统一社会信用代码（USCC） | 唯一主键；**强烈建议**，比按名称匹配可靠得多 | 强烈建议 |
| 简称 / 来源别名 | 来源系统里实际出现的写法（如"中燃宜昌公司""浦华三峡水务"） | 必填 |
| 业务类型 | water / gas / lpg | 必填 |
| 服务区域 | 区县或更细（用于歧义消解） | 必填 |
| 状态 | 启用 / 停用（历史更名请给生效时间段） | 必填 |

### 2.2 机构主数据（并列需求，容易被忽略）

真实数据里的承办单位**大部分不是企业**：街办、镇、住建局、城市运行管理中心等。它们同样需要一个档案来源，否则 G2 只能匹配"企业类"责任单位，其余全部落到待匹配。

### 2.3 网格主数据（顺带）

库中 `service_grid` 3 条基线数据的 `district_code` 全为 NULL，导致"按区域筛网格"恒为 0 条。需要网格编码、名称、所属区划、覆盖范围。

## 4. 需要业务方回答的问题

1. **哪一列是权威的"责任企业"？** `二级单位` 60% 为空且混机构与企业；是否存在平台侧的"责任单位映射表"（来源单位 → 平台企业/机构）？
2. **"浦华三峡水务"的工商全称与 USCC 是什么？** 现库"宜昌市供水总公司"是否应停用/更名？点军区供水有限公司是否已被其吸收？
3. **"中燃宜昌公司" / "宜昌中燃城市燃气有限公司" / "宜昌中燃智慧能源有限公司" 是不是同一法律主体？** 若是，匹配应指向同一个 `enterprise_code`；若不是，需要区分规则。
4. **"夷陵中燃公司""长阳县燃气公司"是独立法人、分公司，还是同一集团的经营区域？**
5. **政府承办单位（街办/镇/局/城运中心）在平台里落到哪张档案表？** 需要新建机构档案，还是复用 `service_grid`？
6. **历史更名怎么处理？** 例：来源正文里同时出现"浦华三峡水务"和"三峡浦华水务"。建议按"别名列表 + 生效时间段"建模，而不是一条记录只存一个名字。
7. **能否提供 USCC？** 有 USCC 就不必依赖中文名称模糊匹配，可靠性完全不同量级。

---

## 5. 拿到数据后的处理方式（提前说明，便于对方判断交付形态）

- 交付形态不限：Excel / CSV / 数据库视图均可；只要有**稳定唯一键（优先 USCC）**。
- 平台侧会以**替换**方式导入（不是追加）：现库 4 条基线数据将被整体替换，并保留替换前快照以便回滚。
- 导入必须以迁移/脚本形式留痕，可重复执行且幂等。
- 拿到之前，G2 的匹配规则保持"未匹配"（`supervision_status='none'` 或敏感命中时 `pending_match`），**不会**用现库数据产生任何交办单。

## 6. 附：本文数据的复现方式

```sql
select json_unquote(json_extract(source_payload, '$.metadata."二级单位"')) unit, count(*) n
from complaint group by unit order by n desc;
```
