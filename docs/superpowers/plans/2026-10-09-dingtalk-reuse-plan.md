## 范围与现有能力

参考入口：https://github.com/pengcong1225-oss/public-utility/tree/docs-dingtalk-reusable-20261009/docs/integrations/dingtalk-login

现有交付是登录方案、配置模板和 Java/Spring 参考实现，未封装独立 SDK。文档中的平台认证中心、OIDC 签发、跨项目单点退出是未来演进，不能作为 gqxq 当前可调用的已交付服务。gqxq 保持直接接入单位钉钉组织的选择，通过适配既有实现复用规则及测试。

## 用户初始化与培训口径

1. 实施人员幂等建立首位本地管理员；管理员盘点现有账号、手机号唯一性和人员归属，配置角色与数据范围。
2. 普通单位人员无需提前批量建号，也不需要把钉钉通讯录整批导入 gqxq 才能登录。
3. 第一次扫码或 H5 登录，由服务端核验企业身份 `(corpId, dingUserId)`。个人 unionId 需换取配置企业的 userid，前端自报 userid/手机号不可作为身份依据。
4. 已有有效绑定直接复用本地 userId；没有绑定时，仅用服务端取得的完整、规范化手机号唯一匹配旧账号。不得按姓名或用户名猜测；手机号缺失/打码/多账号匹配/绑定冲突均转管理员处理。
5. 找到唯一旧账号时关联原账号，保留管理员已维护的账号类型、角色与范围；没有匹配时创建基础身份，账号类型为“未确认”（unknown），初始没有业务角色、组织或数据范围，进入“业务权限待分配”页面。
6. 管理员核实人员归属、维护账号类型并授权后才能办理业务。能通过钉钉登录不等于能查看全部诉求，更不等于管理员；企业、部门、钉钉管理员身份及平台角色均不能自动推断内部人员类型。
7. 停用或撤销绑定必须生效；解绑/撤销时同步递增本地会话版本，使既有 JWT 下一次请求失效，不能只阻止下次登录。解绑保留撤销记录，不允许下一次扫码无条件自动重新绑定。后续手机号变化不自动改绑既有身份。

需要准备的是管理员、旧账号核对和授权表，而不是全员账号预置表。单位通讯录同步属于另一项能力，本参考登录流程不代表已交付通讯录同步。

## 与 A5/A2 的衔接

| 责任 | gqxq 保持的边界 | 复用适配要求 |
|---|---|---|
| 人员主键 | app_user.user_id 稳定，历史业务记录不改主键 | 钉钉身份映射到已有或新建本地 userId |
| 账号类型 | C3 的 internal/enterprise/unknown 由管理员明确维护 | 新外部身份默认 unknown，已有绑定保留已维护类型；不得根据钉钉部门或角色推断 internal |
| 业务角色 | A5 可配置角色；已有业务用户一人一档 | 尚未授权基础身份允许零业务角色，不能默认赋 readonly/handler |
| 对象范围 | A2 单规则交集、多规则并集；无规则拒绝 | 新基础身份零范围，不继承钉钉部门或管理员身份的业务授权 |
| 会话 | gqxq 当前 Bearer JWT 与版本失效机制 | 参考使用 Cookie 会话；按 gqxq 会话服务适配，不共享 Cookie/密钥，不将 token 放入 URL |
| 当前身份 | A5 resolveAuthorization 与 A2 resolveAccessContext | 两种钉钉入口使用同一账号解析；每次业务请求执行当前本地授权 |
| 待授权页面 | 仅本人身份信息/退出等自服务 | 认证成功而无业务权限时展示待分配，不放行业务 API |
| 本地账号 | 保留初始化、改密、重置和受控停用 | 不因钉钉接入删除既有账号管理及必要的管理员恢复能力 |

A5 当前本地人工建号仍要求明确选择业务角色；未来自动基础身份创建是独立受控路径。A2 对旧账号保留全域权限的迁移只覆盖迁移当时的明确名单，不能覆盖将来的自动建号。

## 复用与必须适配的部分

- 可复用设计和测试：企业身份核验、手机号规范化/唯一匹配、绑定冲突/撤销、浏览器 state 及 nonce、授权码防重放、并发首登和事务规则。
- 纯钉钉账号的凭据类型需单独定义；不能把参考项目的占位密码散列直接写入 gqxq 的 bcrypt 本地登录链路。初始改密/管理员重置对纯外部身份的规则后续明确。
- 需移植到 Express/TypeScript：参考 Java 通信组件、账号/绑定仓储、控制器、锁与事务、审计及会话对接。参考的移动免登入口当前嵌在审批页面，应提取为纯身份入口。
- 钉钉授权码消费独立持久提交；账号/绑定/会话保持事务一致；QR 与 H5 并发首登不能创建重复账号。不能只拷贝一份 V55.1 增量 SQL，需按 gqxq 自身迁移序列补齐依赖。
- QR 的服务端浏览器 state 与 H5 请求 state 不是同一机制，分别保留验证和测试。参考 QR state 有效期300秒、单进程内存存储；多实例必须补共享原子消费或明确粘滞及失效处理。
- 新项目配置独立登记 Corp ID、Client ID、Agent ID、回调及应用可用范围，核对手机号权限。登录无需开启通知 worker 或业务外部回调；OAuth 登录回调与业务填报回调分别配置。

## 验收与待办

参考文档记载：电脑授权、手机号自动建号、重复登录复用账号已验证；手机 H5 只有契约测试通过，真实手机仍待验证。本次读取不能视为 gqxq 已完成任何真实登录验收。

后续钉钉适配任务应覆盖：扫码浏览器绑定/过期/重放、H5真实手机、旧账号唯一关联、新基础身份零业务权限、并发首登、停用/撤销/明确重绑、会话失效、站内回跳白名单、失败与取消授权、跨企业拒绝、日志脱敏及 gqxq 业务范围矩阵。形成 gqxq 自己的验收证据后才开启实际登录。
