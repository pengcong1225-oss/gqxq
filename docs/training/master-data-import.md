# 基础数据导入操作说明（b4-v1）

编制日期：2026-10-09。示例均为虚构数据，不能直接作为业务数据。入口在字典、企业、网格维护页的“模板与导入”，批次页在 `/master-data/imports`。

## 权限与步骤

所有导入、批次查询、确认和错误下载都需要 `masterdata.import` 加目标维护能力：字典/分类为 `system.dict.manage`，企业/部门映射/户数为 `enterprise.manage`，网格/小区/覆盖/边界为 `grid.manage`。只读或必须修改密码的账号不能操作。服务端每次读取当前授权，历史授权、本人批次、admin 角色都不能替代当前对象范围；一期只查询本人批次。

1. 选择类型，下载该类型 XLSX（“数据”“说明”两页）或 CSV 和字段说明；边界下载 GeoJSON。
2. 删除虚构样例，按文本填写稳定编码。CSV 必须为 UTF-8；XLSX 输入必须为文本，保留前导零，日期为真实 `YYYY-MM-DD`，布尔值为 `true/false`。
3. 上传并校验，核对新增、更新、不变、错误数量及分页旧新值。预览不会改动主数据；有任意错误不能确认。
4. 下载错误 CSV，按工作表、行号、业务键、字段和原因修改文件后重新预览。错误 CSV 已作纯文本转义，不含整行源数据或内部异常。
5. 确认后以实际批次结果为准。失败时整批主数据、历史和逐对象审计回滚，实际新增/更新都是 0；修正后新建批次。响应丢失可在批次页查询恢复结果；同批相同请求不会重复执行。

预览有效期 24 小时。过期不能确认或下载错误；原文件和逐行明细由请求处理及每 60 秒清理任务删除。稳定对象授权证明和最终结果保留，因此查询旧结果仍检查当前权限和全批范围。预览后主数据、依赖字典、父项或范围版本变化会返回 409，必须重新上传核对。更换文件、类型或批次会立即废弃原确认，迟到响应不会替换当前预览。

## 模板与依赖顺序

模板位于 `server/templates/imports/`。每类 `*-fields.md` 是同版字段契约，10 类提供 XLSX/CSV；边界提供 GeoJSON。同类成功虚构文件即主模板，失败文件在 `examples/*-invalid.csv` / `grid_boundary-invalid.geojson`，失败条件见该目录 README。

| 类型 | 稳定键与重点 | 前置数据 |
|---|---|---|
| dictionary_type | code；不可导入状态机只读类型 | 维护授权 |
| dictionary_item | typeCode + code；parentCode，最多两级 | 字典类型；支持同批新父项与新子项 |
| category | 正式大小类 code；父项稳定编码 | 固定 complaint_category 类型 |
| enterprise | enterpriseCode；类型一致，停用须依据 | 已发布启用 business_type/district 选项 |
| department_mapping | sourceSystem + sourceDepartmentCode；aliases 为 JSON 字符串数组 | 登记企业；不按名称自动合并 |
| household | enterpriseCode + validFrom；非负整数，空为未知，0 为真实零 | 登记企业 |
| admin_grid | code；所属 districtCode | 已发布启用 district |
| community | code；adminGridCode | 行政网格 |
| service_grid | code/name/enterpriseCode/businessType；仅登记身份 | 启用登记企业、业务类型；显式全域管理员 |
| grid_coverage | 每行一条 admin_grid/community 关系；同 code 构成完整覆盖集合 | 已登记服务网格、行政网格、小区 |
| grid_boundary | 现有行政网格 code；WGS84 来源声明 | 行政网格；权威边界 |

建议顺序：字典类型→字典条目/正式分类→企业→户数/来源映射→行政网格→小区→服务网格登记→完整覆盖。权威边界可在建立覆盖前导入，以便首个覆盖版本包含几何。文件中没有的对象不会删除或停用；企业可选列缺失表示保留，明确提供空值清除可空文本。其他必需列必须保留。编码不支持改绑，已引用父级及历史沿用 B1—B3 保护规则。

## 服务网格首次初始化

这是显式全域管理员操作：`grid.manage` 与显式 `all` 范围负责登记/首次发布，导入入口还需 `masterdata.import`；草稿读取只需 `grid.read + all`。admin 角色不自动拥有 all。登记后的 `import_state=draft` 没有覆盖 revision、日期区间或几何，也不能作为已维护覆盖进入地图或统计；`legacy` 是既有历史对象，不能当作草稿猜测。发布后使用真实全部覆盖的企业/区划授权。

先用 service_grid 模板登记 `001` 的稳定身份，再用 grid_coverage 模板按真实起始日（例如 `2026-01-01`）填写该网格的全部行政网格和小区关系。无需虚构更早的空覆盖日期。第一次完整覆盖确认在同一事务创建首个覆盖 revision、转 `published`、增加版本并记审计；重复相同身份或覆盖是“不变”。已发布同日覆盖不能覆写；覆盖变更须使用真实更晚的新有效期。登记输入与已有名称、企业或业务不一致会明确拒绝。

grid_coverage 同一网格所有行必须同一有效起止日期，不得重复关系；小区必须属于同批关联的行政网格。预览和执行数量按网格聚合操作计算（两个关系行可能是一个更新），差异中的关系数组展示完整集合；聚合错误标在该集合第一源行。有效期均为 `[validFrom, validTo)`；开放期间可在后续新起点正常结束旧开放期，旧数量和历史版本不覆写。

## 文件约束与审计

单文件最多 10 MiB、2000 数据行；XLSX 实际解压最多 40 MiB、ZIP 条目最多 100、仅数据/说明两页、总单元格最多 100000、文本单元格最多 4096 字节、最大列坐标 64。公式（含共享公式和缓存值）、宏、外链、加密、XML 实体、伪扩展名、损坏或不可靠编码明确拒绝。GeoJSON 总顶点最多 20000，详见边界字段说明；平台不自动转换坐标、不替代缺失边界。

实际逐对象变更保留 B1—B3 原审计链。导入聚合摘要是一期全域审计规则：只有当前 `system.audit.read + explicit all` 可见，摘要只含稳定批次号、类型、版本、数量和结果，受限人员通过当前全批授权的本人批次查看结果。无变化批次不新增主数据版本、历史或变更摘要。
