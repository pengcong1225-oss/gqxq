# 人工回访操作

日期：2026-10-09。入口：诉求详情 →「人工回访」。只记录人工完成的回访事实，不自动拨号或录音。

1. 有「查看诉求」能力（complaint.read）和当前诉求数据范围可查看来源坐席评价、人工回访、主管结论和「查看版本历史」。来源值与本地值独立；无法安全显示的来源原文只提供说明，授权用户可使用既有「查看来源原件」。Q5 正式有效评价和来源优先规则未确认，页面不显示正式满意率。
2. 有「登记人工回访」能力（followup.create）可点「登记回访」，填写回访时间、是否接通、评价和备注。未接通不能填写评价，也不计为不满意；已接通但未取得评价保留为空。不满意必须填写理由。点「保存回访」，失败显示真实错误，确认前保持原内容可重试。
3. 只可更正本人登记的记录。点「更正回访」，核对事实并填写「更正理由」，点「保存更正」。新版本保留旧版本；没有删除或无痕覆盖。版本冲突时页面刷新记录，核对后重新打开更正。更正不会改变既有主管结论。
4. 账号类型为「内部」、有「填写主管结论」能力（followup.conclude）及当前范围时，可点「填写主管结论」，填写「主管结论」「结论理由」，点「保存主管结论」。不需要登记能力；不能替换回访事实评价。「企业」和「未确认」账号不能填写主管结论，旧管理员须先按 [账号初始化说明](../acceptance/abcd/account-initialization.md) 显式维护账号类型。
5. 重试不变的提交沿用同一幂等键，成功结果不会重复落库。更改内容会产生新操作键。版本历史显示各次事实、操作者、理由与主管结论；来源原始数据、诉求交办和办结状态不随回访更改。

当前授权被收回后，即使旧页面或令牌仍存在，服务端也按数据库当前身份、能力和范围拒绝。重新导航或取得最新授权后页面清空旧数据和操作入口；切换诉求时旧异步结果不能填回新诉求。

本轮真实 SQL 在专用 gqxq_c3_contract_test 执行。新进程读取持久回访的证据只说明该组件落库/重新读取，不代表完整部署、恢复或生产环境验收。
