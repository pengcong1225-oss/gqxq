## 1. 接口概览

| 项 | 值 |
| --- | --- |
| 方法 / 路径 | `GET /api/v1/assessment/admin-boundaries` |
| 鉴权 | **必需**，`Authorization: Bearer <token>`（token 由 `POST /api/v1/auth/login` 取得） |
| 权限码 | `assessment.read`（`rolePolicy.ts`：`GET /^\/assessment\/(?:admin-grids\|admin-boundaries\|grid-comparison\|historical\|seasonal)$/` → `permissionCode: 'assessment.read'`） |
| 请求参数 | **无**（不接受任何 query） |
| 响应封套 | `{ code, message, data }`，成功时 `code=200` 且 HTTP 200；失败时 HTTP 状态码与 `code` 相同 |
| 数据缓存 | 区县边界 12h（服务端内存）；街道边界 30min（服务端内存）。见 §6 |
| 前端调用方 | `gridLayer.ts` → `fetchGridBoundaries()`，复用 `sessionStorage['gqxq-token']` |

**为什么必须走后端（架构约束）**：前端**不持有高德 key、不直接调 `restapi.amap.com`**。原因有三：
① `GQXQ_AMAP_KEY` 是后端 `.env` 凭证，前端不应复制一份；
② 高德返回 **GCJ-02**，必须转 WGS84 才能与 CIM 影像/抖动坐标对齐（否则偏移数百米），而该转换已在后端 `domain/utilityCoordinates` 统一实现，避免两处公式漂移；
③ 边界是低频数据，服务端缓存可避免大屏每次刷新都打高德（免费额度 QPS 很低）。

请求示例：

```bash
curl -s -H "Authorization: Bearer $GQXQ_TOKEN" \
  http://127.0.0.1:3100/api/v1/assessment/admin-boundaries
```

## 2. 响应结构

### 2.1 顶层

```jsonc
{
  "code": 200,
  "message": "success",
  "data": {
    "boundaries": [ /* 见 2.2，区县在前、街道在后 */ ],
    "source": "amap",
    "configured": true,
    "level": "district+street",
    "streetSource": "buffer",
    "streetCount": { "official": 0, "buffer": 41 }
  }
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `boundaries` | `Boundary[]` | 边界数组，**区县 + 街道混在一个数组里**，用 `level` 区分。`[...districtBoundaries, ...streetBoundaries]` |
| `source` | `string` | 顶层边界来源，**当前恒为 `"amap"`**（写在路由里是常量，不代表街道来源；街道来源看 `streetSource`） |
| `configured` | `boolean` | 后端是否配置了 `GQXQ_AMAP_KEY`。前端据此区分「高德 Key 未配置」和「配了但拉取失败」 |
| `level` | `string` | 层级组合，当前恒为 `"district+street"` |
| `streetSource` | `'official' \| 'buffer' \| 'mixed' \| 'none'` | **街道层**边界来源总览，前端状态条与图例据实标注 |
| `streetCount` | `{ official: number; buffer: number }` | 街道边界按来源分项计数（两者之和 = `level==='street'` 的条数） |

`streetSource` 的判定逻辑（`streetBoundaryService` 结果统计）：

| 情况 | `streetSource` | 含义 |
| --- | --- | --- |
| `official>0 && buffer==0` | `official` | 全部街道已是甲方正式边界 |
| `official>0 && buffer>0` | `mixed` | 部分正式、部分缓冲近似（**灌数过渡期常见**） |
| `official==0 && buffer>0` | `buffer` | 全部街道为点位缓冲近似（**当前状态**） |
| 都没有 | `none` | 无街道面，前端退回「质心气泡」兜底 |

### 2.2 `boundaries[]` 单项

区县与街道**共用同一契约**，仅 `level`、`source`、`pointCount` 取值不同：

```jsonc
// 区县（高德真实行政边界）
{
  "code": "420502",
  "name": "西陵区",
  "level": "district",
  "polygons": [ [ [111.2xx, 30.xx], [111.2xx, 30.xx], /* … */ [111.2xx, 30.xx] ] ],
  "source": "amap"
}

// 街道（当前：点位缓冲区合并）
{
  "code": "420502001",
  "name": "西陵街道",
  "level": "street",
  "polygons": [ /* 1..N 个环，每环 ≥4 点，首尾闭合 */ ],
  "source": "buffer",
  "pointCount": 56
}

// 街道（甲方几何灌入后）
{
  "code": "420502001",
  "name": "西陵街道",
  "level": "street",
  "polygons": [ /* 来自 admin_grid.geometry */ ],
  "source": "official"
}
```

| 字段 | 类型 | 区县 | 街道 | 说明 |
| --- | --- | --- | --- | --- |
| `code` | `string` | 6 位 | 9 位 | 行政区划码 / 网格码。规则见 §3 |
| `name` | `string` | 是 | 是 | 展示名称。区县取自 `YICHANG_DISTRICTS` 常量（回退高德 `name`）；街道取自 `admin_grid.name`（缺失回退 `code`） |
| `level` | `'district' \| 'street'` | `district` | `street` | 层级。前端据此选样式（见 §7） |
| `polygons` | `number[][][]` | 是 | 是 | **已转 WGS84** 的多边形环数组：`[环][点][lon,lat]`。**一个环 = 一个独立多边形**（不是 GeoJSON 的「外环+孔洞」语义），前端每个环建一个 `ol/geom/Polygon` |
| `source` | `'amap' \| 'buffer' \| 'official'` | 恒 `amap` | `buffer` 或 `official` | 该条边界的来源，见 §4 |
| `pointCount` | `number`（可选） | **不返回** | 仅 `buffer` 时返回 | 参与生成缓冲区的点位数。`official` 与区县均无此字段 |

**`polygons` 的关键语义**：后端把 Polygon 与 MultiPolygon 统一拍平成「环的扁平数组」。
- `admin_grid.geometry` 单个 `Polygon`（可能带孔洞）→ 拍平成 N 个环；
- `MultiPolygon` → 所有子多边形的所有环一起拍平；
- 因此前端拿到的 `polygons.length` 可能 >1，**每个环单独着色/描边**（同一个 `code` 会生成多个 Feature，件数相同）。

### 2.3 实测样本（2026-11-19，当前库）

## 3. 两级编码规则

| 层级 | 长度 | 示例 | 来源表 | 说明 |
| --- | --- | --- | --- | --- |
| **区县** | **6 位** | `420502` 西陵区 | `YICHANG_DISTRICTS` 常量（与 `admin_grid` 的 6 位码一致） | 走高德 `/v3/config/district` 拿真实边界 |
| **街道（网格）** | **9 位** | `420502001` 西陵街道 | `admin_grid.code`（`CHAR_LENGTH(code)=9`） | 前 6 位 = 所属区县码 |

规则要点：

1. **长度即层级**：`code.length === 6` → 区县；`code.length === 9` → 街道。后端 `loadStreetBoundaryInput` 用 `CHAR_LENGTH(code)=9` 取街道，前端 `renderGridCentroids` 用 `code.length !== 9` 排除区县。
2. **前 6 位是区县归属**：`code.slice(0, 6)` 即父级区县码（用于区县维度的收窄过滤）。
3. **宜昌区县基线（13 个，后端常量顺序即返回顺序）**：

   | 码 | 名称 | 码 | 名称 |
   | --- | --- | --- | --- |
   | `420502` | 西陵区 | `420527` | 秭归县 |
   | `420503` | 伍家岗区 | `420528` | 长阳土家族自治县 |
   | `420504` | 点军区 | `420529` | 五峰土家族自治县 |
   | `420505` | 猇亭区 | `420581` | 宜都市 |
   | `420506` | 夷陵区 | `420582` | 当阳市 |
   | `420525` | 远安县 | `420583` | 枝江市 |
   | `420526` | 兴山县 | | |

4. **`admin_grid` 实际存量（实测）**：`124` 条 = 6 位 `14` 条 + 9 位 `110` 条。
   注意 6 位有 **14** 条而高德只拉 **13** 个区县 —— 多出的一条是**高新区兜底码**（高德无独立行政边界，见 §8）。所以：
   - `admin_grid` 里 6 位码 ≠ 一定有边界；
   - 前端 `gridLayer.ts` 判定「区县不足 13/13」时会在状态条提示 `区县边界 N/13（其余无独立边界或拉取失败）`。
5. 9 位街道码在 `admin_grid` 有 **110** 条，但**只有 41 条**能生成边界 —— 因为只有 `41` 个街道在 `community` 表里挂了带坐标的小区点位（`COUNT(DISTINCT admin_grid_code)=41`）。其余 69 条无点位、无几何，**不会出现在响应里**。

## 4. 数据来源对照表

| 层级 | 来源 | 实现 | 坐标系 | 缓存 | 现状 | 响应中 `source` |
| --- | --- | --- | --- | --- | --- | --- |
| 区县（6 位） | **高德 restapi** | `GET {AMAP_BASE}/v3/config/district?keywords=<adcode>&subdistrict=0&extensions=all`，解析 `polyline`（`;` 分点、`\|` 分环） | 高德返回 **GCJ-02** → 后端 `utilityGcj02ToWgs84()` 转 **WGS84** | 12h + 单飞（`inflight`） | ✅ 13 个区县 | `amap` |
| 街道（9 位） | **点位缓冲区合并**（兜底） | 取 `community.jitter_lng/lat`（缺失回退 `location_lng/lat`）按 `admin_grid_code` 分组 → 每点 `@turf/buffer` 半径 **800m**（`steps: 8`）→ `@turf/union` 合并 → 拆环，坐标 `.toFixed(7)` | 已是 **WGS84**（与 CIM/抖动点位同源） | 30min + 单飞 | ✅ 41 个街道 | `buffer` |
| 街道（9 位） | **甲方正式边界** | `admin_grid.geometry`（JSON 列）有值即用，`polygonsFromGeoJson()` 提取环 | **必须 WGS84** | 30min（需主动失效） | ❌ **待接入**：124 条全 NULL | `official` |

**街道分级策略（`buildStreetBoundaries`）**，对每个 9 位码依次：

1. `admin_grid.geometry` 能解析出 ≥1 个环 → `source: 'official'`，直接用甲方几何，**不掺缓冲**；
2. 否则用同街道小区点位做缓冲区合并 → `source: 'buffer'`，附 `pointCount`；
3. 点位数为 0（或为 1 个点且缓冲失败）→ **跳过该街道**，不返回。

> 相邻街道的缓冲面**允许轻微重叠**（真实街道本就相邻），后端不做互相裁切。

**800m 半径的调参依据**（源码注释实测记录）：

| 半径 | 效果 |
| --- | --- |
| 300m | 同街道点位间大量空洞，一个街道碎成 4~7 个孤岛（视觉破碎） |
| 600m | 多数街道合并成 1~2 块，边缘仍有少量碎块 |
| **800m** | 街道内部基本连成整块；相邻街道有所重叠（可接受），≈步行 10 分钟 |

**为什么不用凸包**：点位沿江/沿路带状分布时凸包会退化成细长条，跨几公里，与街道实际形状严重不符（实测出现黄色/蓝色大长条横贯全图）。缓冲区合并不拉长条、位置完全由真实点位推导，**不虚构**。

## 5. 甲方正式边界接入契约

### 5.1 落库位置

写入 **`admin_grid` 表**（MySQL），关键列：

| 列 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `code` | `varchar(64)` **PK** | 9 位街道码 | 必须已存在于 `admin_grid`（110 条 9 位码） |
| `name` | `varchar(128)` NOT NULL | | 展示名称 |
| `district_code` | `varchar(64)` NOT NULL | 6 位区县码 | 必须为已发布启用的区划字典编码 |
| `version` | `bigint unsigned` NOT NULL | 乐观锁 | 每次写入 +1，必须回传 `expectedVersion` |
| **`geometry`** | **`json` NULL** | 可为 NULL | **甲方正式边界的 GeoJSON geometry 对象** |
| `coordinate_system` | `varchar(16)` NULL | 有几何时**必须** `'WGS84'` | 有 `geometry` 则非空，无几何则必须为 `NULL` |
| `geometry_source` | `varchar(500)` NULL | 有几何时**必须**非空 | 授权来源说明，如 `甲方2026-11批次正式边界（市资建局）` |

### 5.2 推荐写入路径：`POST /api/v1/admin-grids`

**不要直接 `UPDATE admin_grid.geometry` 绕过校验。** 系统已有带完整几何校验的写入接口：

| 项 | 值 |
| --- | --- |
| 方法 / 路径 | `POST /api/v1/admin-grids` |
| 权限码 | `grid.manage`（`rolePolicy.ts`：`POST /^\/admin-grids$/`） |
| 服务实现 | `serviceGridService.saveAdmin()` → `validateAdminInTx()` → `saveAdminInTx()` |
| 副作用 | `version+1`、写 `audit_log`（`ADMIN_GRID_SAVE`） |
| 查询回读 | `GET /api/v1/admin-grids/:code`（`grid.read`） |

请求体（`adminGridSchema`，`.strict()` —— **多一个字段就报错**）：

```jsonc
{
  "code": "420502001",
  "name": "西陵街道",
  "districtCode": "420502",
  "expectedVersion": 0,                       // 当前库该行的 version
  "geometry": { "type": "Polygon", "coordinates": [ /* … */ ] },
  "coordinateSystem": "WGS84",                // 字面量，只接受 "WGS84"
  "geometrySource": "甲方2026-11批次正式边界（市资建局）",
  "expectedDistrictVersion": 3                // 可选：区划字典版本
}
```

清空几何（回退到缓冲兜底）时：`geometry=null`、`coordinateSystem=null`、`geometrySource=null`（三者的空/非空必须一致，否则报 `几何须带 WGS84 坐标系和授权来源；无几何时元数据为空`）。

### 5.3 GeoJSON 结构要求

**只支持 `Polygon` / `MultiPolygon`**，且 `geometry` 对象**只允许 `type` 和 `coordinates` 两个键**（多键报 `几何字段无效`）。

#### Polygon（单块，可带孔洞）

```jsonc
{
  "type": "Polygon",
  "coordinates": [
    [                                   // 环 0 = 外环（必填）
      [111.2900000, 30.6950000],
      [111.2980000, 30.6950000],
      [111.2980000, 30.7020000],
      [111.2900000, 30.7020000],
      [111.2900000, 30.6950000]         // 必须与首点完全相等 → 闭合
    ],
    [                                   // 环 1+ = 孔洞（可选，必须完全在外环内）
      [111.2930000, 30.6970000],
      [111.2950000, 30.6970000],
      [111.2950000, 30.6990000],
      [111.2930000, 30.6970000]
    ]
  ]
}
```

#### MultiPolygon（多块不连通区域，如飞地/跨江）

```jsonc
{
  "type": "MultiPolygon",
  "coordinates": [
    [ /* 子多边形 1：环数组，同 Polygon.coordinates */ ],
    [ /* 子多边形 2 */ ]
  ]
}
```

> ⚠️ **MultiPolygon 的子面之间不允许相交或互相包含**（校验会报 `MultiPolygon 面重叠或相交，请使用分离的权威几何`）。重叠/相接的区域请先在 GIS 侧合并成一个面再提交。

#### 校验规则清单（`validateGeometry()` / `ring()` / `polygon()` 实际实现）

| # | 规则 | 失败提示 |
| --- | --- | --- |
| 1 | `type` 只能是 `Polygon` / `MultiPolygon` | `只支持 WGS84 Polygon/MultiPolygon` |
| 2 | 对象只有 `type`、`coordinates` 两个键 | `几何字段无效` |
| 3 | `Polygon` 的环数 1~100 | `多边形无效` |
| 4 | `MultiPolygon` 的子面数 1~100 | `多边形无效` |
| 5 | **每个环点数 4~10000**（闭合环最少 4 点 = 三角形） | `几何环长度无效` |
| 6 | 每个点是长度为 2 的数组，且为**有限数字** | `WGS84 几何必须为闭合有效二维坐标环` |
| 7 | **`|lon| ≤ 180` 且 `|lat| ≤ 90`** | 同上 |
| 8 | **首点必须与末点完全相等（闭合）** | 同上 |
| 9 | 不允许零长边（相邻两点完全相同） | `几何存在零长边` |
| 10 | **环不能自相交** | `几何环自相交` |
| 11 | **面积不能为零**（`|shoelace| < 1e-12`） | `几何面积为零` |
| 12 | 孔洞必须在外环内、且不与外环相交 | `多边形孔洞须在外环内` |
| 13 | 孔洞之间不能重叠/相交/互相包含 | `多边形孔洞重叠` |
| 14 | `MultiPolygon` 子面之间不能重叠或包含 | `MultiPolygon 面重叠或相交，请使用分离的权威几何` |

### 5.4 坐标系：**必须 WGS84，禁止 GCJ-02**

| 项 | 要求 |
| --- | --- |
| **允许** | **WGS84**（EPSG:4326，经纬度顺序 **`[lon, lat]`**，即 `[经度, 纬度]`，GeoJSON 标准顺序） |
| **禁止** | **GCJ-02（火星坐标）**、**BD-09**、**Web 墨卡托（米制）**、任何投影坐标 |
| 落库声明 | 有 `geometry` 时 `coordinate_system` **必须**写 `'WGS84'`（字面量，其余值被 schema 拒绝） |

**为什么禁止 GCJ-02**：CIM 影像（EPSG:4490）与小区抖动点位都是 WGS84。若灌入 GCJ-02，宜昌城区会出现**约 680m 的系统性偏移**，表现为整块网格面相对底图与点位整体斜移，且不同纬度偏移量不同，无法用单一平移修正。

**若甲方交付的是高德/腾讯/百度数据**，入库前必须先纠偏：

| 甲方交付坐标系 | 处理 |
| --- | --- |
| WGS84 / CGCS2000（民用精度可视为等价） | 直接入库 ✅ |
| **GCJ-02**（高德、腾讯、多数政务「天地图火星版」） | 用 `server/src/domain/utilityCoordinates.ts` 的 `utilityGcj02ToWgs84()` 逐点转换后再入库 |
| BD-09（百度） | 先 BD-09→GCJ-02，再 GCJ-02→WGS84 |
| 投影坐标（如 CGCS2000 / 3-degree Gauss-Kruger，单位米） | 先用 GIS 工具（QGIS / GDAL `-t_srs EPSG:4326`）反投影成经纬度，再入库 |

> 校验只能看数值范围，**无法识别 GCJ-02**（GCJ-02 的经纬度同样落在合法范围内）。所以坐标纠偏必须在入库前由数据方保证，接口层无法兜底。

### 5.5 坐标精度建议：**7 位小数**

| 小数位 | 约合地面精度 | 建议 |
| --- | --- | --- |
| 5 位 | ~1.1 m | 偏粗 |
| 6 位 | ~0.11 m | 可用 |
| **7 位** | **~1.1 cm** | **推荐**（与后端缓冲结果的 `.toFixed(7)` 口径一致） |
| 8+ 位 | < 1 mm | 无意义，徒增 JSON 体积 |

> 建议统一输出 7 位小数并**去掉末尾冗余**，同时保证首末点**字符串级完全相等**（闭合判定是 `isDeepStrictEqual`，`111.29` 与 `111.2900000` 在 JSON 里都是同一数字，不会被判不等；但写成 `111.29` 与 `111.2900001` 会被判**未闭合**）。

### 5.6 环闭合要求

- **强制**：每个环的**最后一个点必须与第一个点完全相同**（校验项 8）。
- 不闭合 → `WGS84 几何必须为闭合有效二维坐标环`，整个请求被拒。
- 内环（孔洞）同样需要闭合。
- 环方向（顺时针/逆时针）：**当前不校验**，右手法则（外环逆时针、内环顺时针）非强制。但建议按 RFC 7946 输出右手法则，便于后续接入严格校验的 GIS 工具链。

### 5.7 入库前自检清单

- [ ] 目标是 9 位街道码，且已在 `admin_grid` 存在（`GET /api/v1/admin-grids/:code` 能查到）
- [ ] 坐标是 **WGS84**（不是 GCJ-02），顺序为 `[lon, lat]`
- [ ] `lon ∈ [-180,180]`、`lat ∈ [-90,90]`；落在宜昌范围（约 `lon 110.2~112.0`、`lat 29.6~31.4`）—— 可用作粗筛
- [ ] 每个环首末点相同，点数 ≥4
- [ ] 无自相交、无零长边、无非零面积
- [ ] 孔洞在外环内、孔洞互不重叠
- [ ] MultiPolygon 子面互不相交/包含
- [ ] `coordinate_system='WGS84'`、`geometry_source` 已填
- [ ] 传了正确的 `expectedVersion`
- [ ] 入库后调 `GET /api/v1/assessment/admin-boundaries` 确认该码的 `source` 已变 `official`

## 6. 切换机制：几何有值即自动切 `official`

### 6.1 切换链路（前端零改动）

```
admin_grid.geometry 有值
        │
        ▼
loadStreetBoundaryInput()  SELECT code,name,geometry FROM admin_grid WHERE CHAR_LENGTH(code)=9
        │   geometry 非空且能 JSON.parse → officialGeometry.set(code, geom)
        ▼
buildStreetBoundaries()    ① polygonsFromGeoJson(officialGeometry.get(code)) 命中
        │                    → push({ source: 'official', polygons: rings })
        │                    （有 official 就不再算 buffer）
        ▼
路由统计                   officialCount++ → streetSource='official'|'mixed'
        ▼
GET /assessment/admin-boundaries   → boundaries[].source='official', streetCount.official++
        ▼
前端 gridLayer.ts          streetSource / streetCount 原样透传
        ▼
Map2DView.vue gridStyle()  街道描边由 [3,3] 虚线（buffer）改为 [5,3] 实感虚线（official）
状态条 boundarySourceLabel() 显示「街道 41（正式边界）」或「（正式 12 / 近似 29）」
```

**结论：前端、路由、响应契约都不用改。** 甲方只需把几何写进 `admin_grid.geometry`，前端下次拉边界即自动切换。

### 6.2 ⚠️ 缓存 30 分钟 —— 需主动失效才立即生效

街道边界在**服务端内存**缓存 **30 分钟**（`streetBoundaryService.ts`：`CACHE_TTL_MS = 30*60*1000`），且带单飞（`inflight`）。因此：

| 操作 | 生效延迟 |
| --- | --- |
| 关卡后什么都不做 | **最长 30 分钟**（甚至更久，见下） |
| 调 `invalidateStreetBoundaryCache()` | **立即**（下一次请求即重算） |
| 重启后端进程 | 立即（内存缓存随进程消失） |

⚠️ **「最长 30 分钟」是有前提的**：缓存是**懒失效** —— 只有在**有请求进来时**才会检查 TTL。如果大屏 30 分钟内一直没人刷新，第 31 分钟的第一个请求才会重算。更要注意：**大屏页面前端自己会反复拉这个接口**（每次 `loadSpatial` / 边界加载），所以只要有活跃会话，缓存在 30 分钟内一定不会更新。

**推荐做法**：灌数完成后，在服务端代码里调用一次 `invalidateStreetBoundaryCache()`；生产上最省事的是**灌完数重启后端**，或给灌数脚本加一个受控的失效入口。

`invalidateStreetBoundaryCache()` 的签名与位置：

```ts
// server/src/services/streetBoundaryService.ts
export function invalidateStreetBoundaryCache(): void {
  cache = null;
  inflight = null;
}
```

若要通过脚本/运维手段触发，需注意当前**没有对外暴露的 HTTP 失效端点**（`businessFeatures.ts` 中没有），属于已知缺口，见 §8。

**区县缓存是另一套（12h）**：区县来自高德、与 `admin_grid` 无关，灌街道几何**不影响**区县缓存，也不需要清它。

### 6.3 灰度 / 混合期

灌数可以**按街道逐个进行**，不需要一次性全量：

| 已灌街道数 | `streetSource` | 状态条文案 |
| --- | --- | --- |
| 0 | `buffer` | `街道 41（点位缓冲近似）` |
| 部分 | `mixed` | `街道 41（正式 12 / 近似 29）` |
| 全部 | `official` | `街道 41（正式边界）` |

回退：把 `geometry` 置 `null`（同时 `coordinateSystem`/`geometrySource` 置 `null`）→ 该街道下次缓存刷新后自动退回 `buffer`。

## 7. 前端渲染口径

### 7.1 热力五色（标书 1.2.4）

件数 → 颜色按「**占当前最大值 `complaintMax` 的比例**」分档（`Map2DView.vue` 的 `heatColor()`）：

| 档位 | 比例 `count / max` | 颜色（RGBA） | 图例文案 |
| --- | --- | --- | --- |
| ① | `< 0.2` | `rgba(46, 204, 113, 0.42)` | 绿 · 低 |
| ② | `0.2 ~ 0.4` | `rgba(52, 152, 219, 0.46)` | 蓝 · 较低 |
| ③ | `0.4 ~ 0.6` | `rgba(241, 196, 15, 0.5)` | 黄 · 中 |
| ④ | `0.6 ~ 0.8` | `rgba(230, 126, 34, 0.55)` | 橙 · 较高 |
| ⑤ | `≥ 0.8` | `rgba(231, 76, 60, 0.6)` | 红 · 高 |

- `complaintMax` = `gridMetrics` 中 `count > 0` 的最大值；**没有数据（0 或未出现在 metric 里）不着色**，只用描边 —— 避免把「0 件」误读成「没诉求 = 安全」。
- 口径注解：此处是**相对分档**（对当前最大值归一），不是绝对阈值分档。诉求大屏「统计卡/图例」里的 `charts.adminGrid` 与筛选条「网格」下拉**同源**，保证地图热力与面板件数口径一致。

### 7.2 图层视觉分工（区县 vs 街道）

| 属性 | 区县（`level='district'`） | 街道（`level='street'`） |
| --- | --- | --- |
| **填充** | 热力色 **× 0.38 低透明度**（原 alpha ÷100×0.38，如 `0.6 → 0.228`）；无色时为 `rgba(255,255,255,0.015)` | **热力色原值**（`0.42~0.6`）→ **街道是热力主体** |
| **描边颜色** | `rgba(120, 220, 205, 0.7)` 青 | `buffer` → `rgba(150, 200, 255, 0.35)` 蓝；`official` → `rgba(120, 220, 205, 0.45)` 青 |
| **描边宽度** | **1.2**（实线粗边，分区参考） | **0.8**（细边） |
| **线型 `lineDash`** | `undefined`（**实线**） | `buffer` → `[3, 3]`（**细虚线**）；`official` → `[5, 3]` |
| **标签** | `resolution < 0.006` 时显示 | `resolution < 0.004` 时显示；格式 `名称 件数` |
| **zIndex** | 同层 10 | 同层 10 |

> 设计意图：区县只做**分区参考**（淡、粗、实线、低透明填充，不压底下街道），街道是**着色主体**（浓、细虚线）。
> 三维状态下的「选中」另由 `highlightLayer`（`#ffe57a`，width 2.5，填充 `rgba(255,229,122,0.08)`）表达 —— 但**当前只对区县生效**（`renderHighlight()` 只匹配 `props.districtCode`）。街道选中的黄边由 `gridStyle` 的 `selected` 分支承担。

### 7.3 选中态样式

| 状态 | 判定 | 视觉 |
| --- | --- | --- |
| 区县选中 | `level==='district' && b.code === props.districtCode` | 描边 `#ffe57a`（黄）、width **2.4**、**取消虚线**；另有 `highlightLayer` 叠一层黄边 2.5 |
| **街道选中** | `level==='street' && b.code === props.gridCode` | 描边 **`#ffe57a` 黄色**、width **2.4**、**取消虚线**（`lineDash: undefined`） |
| 悬停 | `pointermove` 命中点/网格 | 光标 `pointer` + 顶部浮层「名称 / N 件诉求」 |

## 8. 已知限制

| # | 限制 | 证据 | 影响 / 应对 |
| --- | --- | --- | --- |
| 1 | **高德对街道不返回 `polyline`** | 实测确认：高德 `/v3/config/district` 的街道级 `polyline` 为空（街道不是独立行政区）。源码 `adminBoundaryService.ts` 注释明确记录 | 街道边界**只能**来自甲方几何或缓冲兜底。即使 `subdistrict=1` 也拿不到（注释：`=1 时子级（街道）polyline 为空`） |
| 2 | **`admin_grid.geometry` 目前 124 条全 NULL** | 实测：`SELECT COUNT(*)=124, SUM(geometry IS NOT NULL)=0`（6 位 14 条 + 9 位 110 条，均无几何） | 当前 `streetSource='buffer'`，全部街道走 800m 缓冲近似。**这是本契约待解决的唯一阻塞项** |
| 3 | **街道边界是近似形状，非权威边界** | `source='buffer'`，`pointCount` 为参与点位数 | 面形状由小区点位推导，**边缘不可作为行政界桩依据**。对外展示/考核口径需注明「近似」。正式边界灌入后自动消除 |
| 4 | **相邻街道缓冲面会重叠** | `buildStreetBoundaries` 不做互相裁切 | 视觉上可接受（真实街道相邻）；但**面积统计/面积占比类指标不可用缓冲面计算** |
| 5 | **110 条 9 位码只有 41 条有边界** | 实测 `COUNT(DISTINCT community.admin_grid_code)=41` | 其余 69 个街道无点位、无几何 → 不出现在响应中。前端地图上无面，只能用质心气泡（`renderGridCentroids`）兜底 |
| 6 | **区县只覆盖 13 个，不含高新区** | `admin_grid` 6 位 14 条，`YICHANG_DISTRICTS` 13 条 | 高新区是**兜底码**（高德无独立行政边界）。前端 `gridLayer.ts` 在区县 <13 时提示 `区县边界 N/13` |
| 7 | **无 HTTP 缓存失效端点** | `businessFeatures.ts` / `grids.ts` 均无失效路由 | 灌数后需重启后端，或由代码内调用 `invalidateStreetBoundaryCache()`；否则最长等 30 分钟 |
| 8 | **校验无法识别 GCJ-02** | `validateGeometry()` 只校验数值范围/拓扑 | 坐标系正确性由数据方保证（见 §5.4） |
| 9 | **环方向不做校验** | `ring()` 未做右手法则检查 | 后续若接入严格 GIS 工具链可能需补 |
| 10 | 顶层 `source` 恒为 `"amap"` | 路由里是硬编码常量 | 不能用来判断街道来源 —— 判断街道来源请用 `streetSource` / `boundaries[].source` |
