# G6 来源对接 · 验收证据（2026-09-17）

> 对应《2026-09-17-诉求平台落地计划.md》G6 批次。只记录实际跑过的结果。
> **真实宜接就办接口尚未提供**，因此本批次按计划只做「适配器契约 + 禁用开关 + 契约测试 + UI 如实显示未接入」。

## 0. 刻意不做的两件事

1. **不实现投机的 HTTP 客户端**。真实接口契约未提供，照猜测写的客户端在联调时必然全部作废，
   更糟的是会诱导人以为「已经对接了」。本批次只定义契约。
2. **配置成未知适配器时不构造假适配器**。`/source-status` 会如实报 `misconfigured:true` 并回退为关闭状态——
   既不静默忽略配置，也不假装对接成功。

## 2. 契约测试（`npm run verify:source-adapter`，PASS 5 / FAIL 0）

| # | 断言 | 实测 |
| --- | --- | --- |
| ① | 状态映射**不猜** | `ACCEPTED→accepted`、`processing→processing` 等正确；`UNKNOWN_XYZ` / 中文状态 / 空串 **一律返回 null**，不映射成任何已知状态 |
| ② | 契约可满足 | 内存假适配器实现同一接口，返回的 sourceId 与请求一致且可映射——真实实现照此写即可 |
| ③ | **同步 SQL 只允许写两列** | 扫源码断言 `update complaint` 的 SET 只含 `source_event_status` 与 `source_synced_at`，不含 reporting_status / closed_* / analysis_* |
| ④ | 开关关闭不返回任何状态 | 默认 `enabled=false`，调用即抛错、**不返回任何来源数据** |
| ⑤ | HTTP 栈 | `POST /complaints/8/source-sync` → **HTTP 501**；同步前后三轴完全一致 |

第 ③ 条是**源码级断言**而非运行时检查：这条不变量（适配器无论成功失败都不得改动填报结果与本系统办结状态）
无法靠一次调用穷尽证明，所以直接钉住「只允许写哪两列」，任何重构让 UPDATE 越界都会被测试拦下。

### 实测响应（原文）

```text
GET /source-status -> 200
  {"adapter":"disabled","enabled":false,"batch":"G6",
   "message":"来源适配器已关闭，来源状态保持「未接入」","misconfigured":false}

POST /complaints/8/source-sync -> 501
  {"code":501,"message":"宜接就办来源适配器未启用（批次 G6）：真实接口待对方提供，本平台不展示模拟的来源进度",
   "data":{"errorCode":"NOT_IMPLEMENTED","batch":"G6"}}

同步前后（必须完全一致）:
  source_event_status unknown -> unknown
  reporting_status   not_started -> not_started
  closed_in_system   false -> false
```

## 3. 界面呈现（三态 + 两处不假装）

| 状态 | 呈现 |
| --- | --- |
| `enabled=false` | **信息级**提示条「来源对接：未接入（批次 G6）」+ 原样服务端 message + 说明「列表中的来源状态一律显示未接入，这是真实状态，不代表异常」 |
| `misconfigured=true` | **警告级**并原样展示服务端 message |
| `enabled=true` | 不显示任何提示条 |
| 状态获取失败 | **不假装未接入**：显示「获取失败」+ 重试，且不影响整页 |
| 尚未取到 | 什么都不显示（拿到真实状态前不做任何断言） |

「同步来源状态」按钮：501 判为**信息级**「适配器未启用，真实接口待对接」而不是泛化错误，也不弹假成功；
仅 `updated=true` 才刷新详情。列表的「来源状态」列**一行未改**，仍是服务端 `sourceEventStatusName`，没有进度语义被改写。

## 4. 本轮暴露的两处过程疏漏（都是我自己的）

| 疏漏 | 后果 | 被谁发现 |
| --- | --- | --- |
| 写了 M9 却**没执行迁移** | `/source-sync` 返回 500 而不是 501 | G6 契约测试 |
| 改了 src 却用**旧的 dist** 测试（上一批次） | 坐标缺陷修复的验证出现假阴性 | 我自己复核时发现 |

两者同类：**改了东西但没把它传播到生效处就去验证**。已把 8 个脚本（4 个验收矩阵 + G6 契约测试 + 2 个桩 + 门禁）全部接进 `server/package.json`，
加上根级 `npm run verify`，常用动作都有入口，减少漏跑一步的空间。
