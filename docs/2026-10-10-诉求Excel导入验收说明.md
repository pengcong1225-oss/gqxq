# 诉求 Excel 导入

## 用户操作

1. 在宜接就办的“综合查询”中导出 Excel，保留原始表头，使用 `.xls` 或 `.xlsx`。
2. 打开“诉求总账”，点击“批量导入”，选择文件，再点击“校验预览”。每批最多 2000 数据行、10 MB。
3. 核对预计新增、跳过及错误数量和行号。有错误时整批不入库，修正原文件并重新上传。预览有效期 24 小时。
4. 点击“确认导入”。完成后总账刷新；可以在“最近导入记录”查看本人批次和结果。遇到网络中断可查询结果或重试确认。

同一文件内相同案件公文号取最后一行（英文字母不区分大小写）；平台已有公文号一律跳过，不覆盖已纠正或处理的内容。确认时重新检查已有案件，因此并发导入可能增加跳过数量。

样本 `20260917170900综合查询.xls` 为 466 数据行、464 个案件公文号；同一案件重复 3 行。供水 200 行、供气 266 行。真实样本只做校验预览，确认入库由验收用户执行。

导入保存原始来话内容、地址、录入时间、业务、诉求性质以及白名单来源信息。不单独保存“市民姓名”“市民电话”两列，摘要隐藏完整手机号；来话内容可能包含联系方式，仍遵循诉求明细查询权限。来源部门和处理结果不自动变成平台责任企业、交办或办结。区域名称能唯一匹配已发布区域字典时写入编码，否则保留原名称。

## 管理员配置与部署

- 执行增量迁移 `20261010090000__complaint_excel_import.js`，不替换已有业务数据。新增 `complaint.import` 能力并赋予内置管理员；其他角色按需授予。
- 使用者同时需要 `complaint.import`、`complaint.read`、显式全域数据范围，且不能为只读角色；完成首次密码初始化后使用。已有账号密码不变。
- `.xls` 解析依赖 Python 3.9+ 和 `xlrd==2.0.2`：在服务器使用 `python -m pip install -r server/scripts/requirements-complaint-import.txt`；必要时将 `COMPLAINT_IMPORT_PYTHON` 设为 Python 可执行文件绝对路径。
- 部署保留 `server/scripts/parse-complaint-export.py`。`.xlsx` 使用现有 Node 依赖，无新增 Node 包。
- 解析不执行公式或宏，拒绝外部链接；上传、解压、单元格、行数、子进程时长及输出均有上限。
- 共享文本展开后及规范化诉求内容每批各不超过 10 MB，超限时按提示拆批；数据库来源键必须使用不区分大小写的排序规则，迁移会检查，不自动修改现有排序规则。
- 仅允许本人读取批次；确认操作重查当前授权并整批事务写入。24 小时后后台清除暂存诉求内容和行明细，保留批次摘要及导入结果；成功批次立即清除待导入内容。
- 审计记录确认人的身份和导入数量，可在日志查询中查看。

## 验收边界

本次本地验收环境是独立的合成数据库，非生产基线。数据库组件测试在另外的独立测试库执行，使用虚构案件检查回滚、并发、重复、过期、撤权及所有权。真实附件不进入仓库夹具或日志。不修改钉钉登录及 E/F 范围。
