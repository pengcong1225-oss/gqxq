## 2. 网关拓扑（现状两套，口径不同）

```
【本机开发 · 3100】
  浏览器/脚本 ──> 127.0.0.1:3100  （M1 后默认只绑回环；非回环地址直连 ECONNREFUSED，见 §4-A1）
                 └─ MySQL 127.0.0.1:3306

【云上实例 · 〈东京 VPS〉】
  公网 ──HTTPS──> nginx:443（〈AI 中转主站域〉，与既有站共用一个 server）
                    ├─ location /gqxq/            -> 前端静态产物
                    ├─ location /gqxq/api/        -> proxy_pass http://127.0.0.1:3100/api/   （带 X-Forwarded-For 等）
                    │                              limit_req 10r/s burst=20、limit_req_status 429、client_max_body_size 1m
                    └─ location /gqxq/api/v1/external/ (+3 条 = 精确匹配) -> **return 403**（入站封闭，放开前不得摘）
                 docker bridge: gqxq-net
                    └─ 127.0.0.1:3100 -> 3100 （gqxq-server 容器；gqxq-mysql 不发布任何宿主机端口）
```

要点：**3100 从未直接暴露公网**；公网到 E1 的唯一通路被 nginx 的 403 挡住。
`/gqxq/api/` 那条反代**已经在发 X-Forwarded-For**，所以 §3 的 `GQXQ_TRUST_PROXY` 取值不是纸面约定，
而是"放开入站那天 remote_ip 记的是客户端还是网关"的直接开关。

## 3. 监听与来源 IP 的配置基线（M1 + M3 的仓库侧）

| 环境 | `GQXQ_HOST` | `GQXQ_TRUST_PROXY` | 为什么 |
| --- | --- | --- | --- |
| 本机开发（3100） | 不设 ⇒ 默认 `127.0.0.1` | 不设 ⇒ 默认 `loopback` | 只绑回环；同机直连时 `req.ip` 就是连接对端，XFF 无从伪造 |
| 裸机 + 本机反代 | `127.0.0.1`（默认） | `loopback`（默认） | nginx 与后端同机 ⇒ 回环对端可信，XFF 里的真实来源被采信 |
| **云上容器形态（现行）** | **必须显式 `0.0.0.0`** | **必须 `private`（等价 `uniquelocal`）或直接写 docker 网关 IP** | 容器里绑 `127.0.0.1` 会让宿主的 `127.0.0.1:3100->3100` 发布端口**不通**；nginx 在宿主，经 bridge 网关进来，`loopback` 不认这个对端 ⇒ XFF 被忽略、`remote_ip` 全记成网关 IP |
| 排障 | — | `true`（会启动打警告） | 任意来源可伪造留痕 IP，**禁止**作为白名单判定或追溯依据 |

代码位置：`server/src/config/env.ts`（`host` / `trustProxy`）、`server/src/index.ts`（显式 bind + 非回环警告）、
`server/src/app.ts`（`applyTrustProxy`，非法取值启动即抛）。
新增 env 已登记进 `server/.env.example`（含 `GQXQ_BASELINE_*` 阈值项）。

⚠️ **部署侧待办（本批未做，属后续部署批次）**：`/data/gqxq/.env` 尚未写入
`GQXQ_HOST=0.0.0.0` 与 `GQXQ_TRUST_PROXY=private`。**在含 M1/M3 的构建上云之前必须先补这两行**，
否则容器起得来但发布端口不通（表现是"health 超时"而非报错），放开入站后 `remote_ip` 还会整片变成网关地址。

## 4. 本批实测证据（串行，全部指向测试库 `gqxq_service_test` 与 33xx 一次性实例）

| 判据 | 结果 | 取证方式 |
| --- | --- | --- |
| **A1** 默认只绑回环；非回环直连失败 | `M1-1..M1-6` **6/6 PASS**：子进程自报 `127.0.0.1:3313`；`192.168.1.39:3313` → `ECONNREFUSED`；显式 `GQXQ_HOST=0.0.0.0` 才可连；非法监听地址 → 退出码 1 且不回落 | `npm run verify:m1`（`server/scripts/verify-bind-host.mjs`） |
| **A2** 收敛监听后可用性未破 | 回环 `GET /health` = 200 且 `database:"up"` | 同上 `M1-2` |
| **A3** `remote_ip` 记到真实来源而非网关（M3 判据） | `M3-1..M3-9` **7/7 PASS**：回环对端带 `x-forwarded-for: 203.0.113.10` ⇒ 库里 `remote_ip=203.0.113.10`；`off` ⇒ `127.0.0.1`；**非回环直连带 XFF ⇒ 记对端真实 IP，XFF 被忽略**；`true` ⇒ 确实可伪造且启动警告；`private` 别名 ⇒ 采信私网对端 XFF；非法取值 ⇒ 启动失败并点名变量 | `npm run verify:m3`（`server/scripts/verify-trust-proxy.mjs`，投递行按 `source_id` 删净并断言归零） |
| **A4** 留痕基线可按日统计四类 + distinct source_id | `M4-1..M4-5` **5/5 PASS**：真实投 6 新建 + 1 同包重投 + 2 非法 + 1 无凭证后，`created/duplicate_same/rejected` 与"演练前 + 本次"逐字段相等 | `npm run verify:m4`（`server/scripts/verify-intake-baseline.mjs`） |
| **A5** 告警能触发一次真实演练（M4 判据） | 阈值调低 ⇒ 判 `ANOMALY` 且退出码 **1**；阈值放宽 ⇒ 退出码 **0**（不空响）；`morgan combined` 真实日志状态码聚合 `{200:7,400:2,401:1}`，解析行数 **10 == 文件里的访问行数 10** | 同上 |
| **A6** 真实库基线现状（只读） | `complaint_source_log` 1399 行**全部落在 2026-09-18 一个日**：`created 464 / duplicate_same 911 / updated 13 / rejected 11`，`distinct source_id=465`，`distinct remote_ip=1` | `cd server && npm run baseline:intake -- --days=200`（只 SELECT） |
| **A7** 本机 3100 重启后的行为前后对比 | **前**：`netstat` = `0.0.0.0:3100` + `[::]:3100`（PID 55932，无 trust proxy）<br>**后**：`127.0.0.1:3100` 单条（PID 10016），启动日志 `trust proxy="loopback"`；`192.168.1.39:3100` → **ECONNREFUSED**；`/health` 200 `database:"up"`；入站端点投 1.5 MB → **413 PAYLOAD_TOO_LARGE**（在进业务处理器之前被拦，**主库 `complaint_source_log` 行数仍 1399 ⇒ 零写入**）；无凭证 `POST /complaints` 与未知 `/external/xxx` 均 **401**（鉴权边界未变）；经 vite dev proxy（`localhost:5173/api` → `localhost:3100`）`/health` **200** ⇒ 收敛 IPv4 回环没打断前端联调；`admin` 登录后 `total=464`、`closedRate=99.1` ⇒ 数据无回归 | 重启后手工探针（见 §8 清单同口径） |

A6 的读法：合法基线就是"**一个投递方 + 一天内一次性批量导入**"。
今后任何一个日子上出现第二个 `remote_ip`、或日均 `created` 从个位数跳到几百，都属"超出基线"，
这正是要在放开入站前先有告警的原因（M4 的默认阈值即按此定：`created>50 / deliveries>200 / rejected>5 / distinct_ip>3`）。
